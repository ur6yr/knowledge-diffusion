## Bounded construction, analysis and deployment extension

The following decisions supersede the earlier milestone-specific availability statements without changing the historical test record.

| ID | Decision and basis |
|---|---|
| D16 | All ten analysis operators now have trusted Python implementations over a complete bounded Neo4j export. This permits one deterministic replay engine. It is an explicit scalability deviation from compiling every general operator to server-side Cypher. Model-written queries are never executed. |
| D17 | Native local ORCID v3, ROR v2, USPTO and mapped PatCit readers supplement OpenAlex. Cross-source links require consistent exact identifiers. Embedding/HNSW resolution and model identity adjudication remain unfinished. |
| D18 | PostgreSQL BYTEA/JSONB artifacts and fenced task/outbox tables are implemented alongside the development file/SQLite backends. Redis accelerates delivery and reconstructs from durable task state. Actual PostgreSQL/Redis service execution is still blocked by missing verified server binaries. |
| D19 | The reconstructed temporal interpretation is a finite observed event trace, not a general timed-automata model checker. Concurrent employment and date uncertainty remain explicit. Bibliometric affiliation observations are excluded from employment transitions. Return-move witnesses require documented departures to license a definite A-to-B-to-A trace. |
| D20 | General witness version 2 selects source and derivation cards with stable weighted greedy coverage and explicit budget relaxation. Complete operands and the full pool remain replay dependencies. Card count is the current display budget unit. Version 1 program witnesses and the original exact-count witnesses retain separate replay support. |
| D21 | Six-way decisions and Partial rewrites are implemented for the supported typed predicates. Synthesis uses full constrained rendering rather than unrestricted prose followed by regex checks. Strong causal templates remain NEI pending a verified external evidence contract. |
| D22 | Live inference is enabled only after authorization, per-run request/token limits, a dated OpenAI cost budget where applicable, and a matching recent capability report. A source-to-answer job shares its budget with capability checks. No paid fallback exists. Multiple independent worker processes do not share a provider spending account and must not be represented as one global cost cap. |
| D23 | Owned launchers use fresh directories, loopback authentication, hostname/generation/expiry checks and child process handles. Logical restore occurs only before readiness in a new empty database. Restoring records and original batch receipts uses staged transactions with final hash verification, not a live filesystem backup. |
| D24 | Co-located vLLM uses an existing verified GPU environment or read-only SIF with read-only model/template binds. Runtime packages and visible GPUs are inventoried. Parser/structured-output support is probed for the actual model. No untested serving lock or hardware sizing for Scout is invented. |
| D25 | Evaluation uses independent stored annotations and complete-item or complete-dialogue bootstrap. Missing benchmarks produce no scores. Baseline/ablation runners and the historical distributed performance architecture remain incomplete. |
| D26 | The existing local XLSX workbook was reused for a two-row discovery pilot with whole-file checksum and exact sheet/row captures. Its August 2024 directory label is not authenticated release metadata and is not substituted for the paper's August 2025 cohort. |
| D27 | Graph integration and logical export acquire the same server-side ownership-node write lock within bounded driver transactions. This waits for an in-flight server transaction even after a dead application releases its host file lock. A live Neo4j concurrency test verifies that export waits and preserves the logical hash. |
| D28 | All twelve reconstructed role prompts describe the current scoped tools and supported scientific policies. Release and task code digests include the prompt files, so prompt changes invalidate the implementation identity and extraction cache dependencies. |
| D29 | Extraction caching defaults off. Explicitly enabled cold and warm fixture runs preserve graph counts. No performance gain is inferred from a cache hit or from mock-model worker timing. |
